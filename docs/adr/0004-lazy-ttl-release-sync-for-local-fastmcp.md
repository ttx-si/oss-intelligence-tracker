# Windows-Safe ETag Release Sync and Three-Tier Fallback for Local FastMCP

Because data ingestion runs in GitHub Actions while `FastMCP` runs on the developer's local machine (often on Windows where open SQLite read handles block file replacement with `PermissionError: [WinError 32]`), relying on local `git pull` or naive file overwrites fails in production. We decided that `FastMCP` will check local `intelligence.db` freshness lazily on tool invocation using a configurable TTL (default 1 hour) and download from the rolling `latest-db` GitHub Release via HTTP `If-None-Match` (`ETag`) negotiation (supporting optional `GITHUB_TOKEN` auth for Private repositories and zero-config access for Public repositories). Before replacing `intelligence.db` with `intelligence.db.tmp`, the sync manager acquires an exclusive thread/process lock and explicitly closes all active SQLite connections so Windows releases file handles cleanly, re-establishing connections only after the swap completes. If offline, `FastMCP` falls back first to the existing local `intelligence.db` with a staleness warning, and finally to compiling `data/schema_data.sql`.
