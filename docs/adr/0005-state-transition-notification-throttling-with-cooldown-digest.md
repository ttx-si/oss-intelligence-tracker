# State-Transition Notification Throttling with 72-Hour Cooldown and Batch Digest

Running high-frequency ingestion every 6 hours causes naive notification logic to spam identical alerts when a repository remains in `SURGING` across consecutive runs or oscillates across the `SURGING`/`SUSTAINED` boundary. We decided to record `last_notified_at`, `last_notified_state`, and `last_curated_notified_at` on each repository, firing high-priority alerts only on upward transitions into `SURGING` when at least 72 hours have elapsed since the last `SURGING` notification, or when `is_curated` is newly set. All qualifying repositories within a run are aggregated into a single Markdown batch digest via `Apprise`, and notification watermarks are committed transactionally only after delivery succeeds.
